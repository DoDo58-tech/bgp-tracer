\section{Data Sources and Ground-Truth Dataset}
\label{sec:data}

A dependable Internet-anomaly attribution system requires a
clean, auditable, and reproducible ground-truth. This
section describes the three data sources BGP Tracer
consumes, the 30-event ground-truth under the the released evaluator
evaluation protocol, the six strict curation invariants,
and the single negative-control event.

\subsection{Data sources}
\label{sec:data-sources}

\paragraph{\cf{} Radar (data plane).}
BGP Tracer consumes the \cf{} Radar API for 5-minute
sampled traffic aggregates on the analysis AS
\cite{cloudflare-radar}. The series is filtered for
regularity ($\mathrm{CV}<0.6$, lag-24 autocorrelation
$>0.4$, $\geq 80\%$ non-zero samples) before being fed
to the traffic agent. \Cf{} Radar's 30-day retention
window is the dominant constraint on the ground-truth;
a third candidate (North Korea 2025-03-18) was admitted
but the cache-rebuild step was killed by a \cf{} Radar
v2 traffic API HTTP~400 validation error; this is the
single no-cache event in the the released evaluator evaluation
(\Sectref{sec:misses}, miss \#3). This is a
graceful-degradation case: the cache-rebuild step is
allowed to fail, and the subsequent steps (detection,
arbitration) produce a valid ``no cache'' output rather
than a crash.

\paragraph{RIPE RIS / RouteViews \rrc{} (control plane).}
BGP Tracer consumes BGP update dumps from \rrc{}
\cite{ripe-ris, routeviews}. The ground-truth
requires a fresh BGP signal at the analysis AS for every
event (invariant~\#2 in \Sectref{sec:dataset-invariants});
the negative control (Starlink 2025-07-24) is the single
event that has no observable routing change in the event window --- a
graceful-degradation case where the routing signal is
allowed to be absent.

\paragraph{CAIDA AS-relationship and RIPE prefix-to-AS
(enrichment).} The \ctpr{} path reconstruction uses
CAIDA's AS-relationship data \cite{caida-asrel} to score
plausibility of the reconstructed AS path, and RIPE NCC's
prefix-to-AS data for AS-path labelling. Both are
stale-able; BGP Tracer downgrades the relationship-inference
confidence when the data is older than 30\,days.

\subsection{ground-truth construction}
\label{sec:dataset-invariants}

The 30-event ground-truth

is constructed under six strict invariants, summarised in
\Tblref{tab:invariants} and \figref{fig:dataset}. The
invariants are the \emph{only} filter applied to the
public-event candidates; no ground-truth label enters the
Phase~1 arbitration logic (\Sectref{sec:arbitration},
\Sectref{sec:threats}).
They are the \emph{dependable-filter} that defines what
counts as a well-formed event before any detection or
arbitration runs.

\subsubsection{Root-cause sub-type distribution}
\label{sec:dataset-subtypes}

The 14 outage events split into 8 distinct root-cause
sub-types (visible in \figref{fig:dataset} right
panel): \emph{announced-space-loss} ($n=5$),
\emph{government-mandated-shutdown} ($n=4$),
\emph{internal-failure-non-BGP} ($n=1$, the negative control),
and the remaining 5 sub-types with one event each
(\emph{firewall-misconfiguration},
\emph{core-router-config-error}, \emph{power-loss},
\emph{cable-cut}, \emph{data-center-routing-fault}).
The 8 route-leak events split into 5 sub-types
(\emph{provider-prefix-rewrite}, \emph{transit-leak},
\emph{internal-config-error}, \emph{BGP-hijack-as-leak},
\emph{MANRS-violation}). The 7 origin-hijack events
split into 3 sub-types (RPKI-bypass, prefix-ownership
dispute, BGP-Forge-Hijack). The 20 distinct sub-types
ensure the strict-accuracy generalises beyond
single-type coverage (\Sectref{sec:threats}).

\subsubsection{The Starlink negative control}
\label{sec:neg-trl}

The Starlink outage on 2025-07-24 is admitted as the single
negative control. Its root cause is a non-BGP internal failure:
AS14593 withdrew at most $0.05\%$ of its BGP routes, so the
BGP-level signal during the event window is statistically
indistinguishable from background noise. The $-11\%$ traffic
drop is a control-plane software fault, not a BGP fault. The
ground-truth cause label is still \emph{outage} (the event was
real downtime), but the root-cause sub-type is a non-BGP
internal failure, which the evaluator treats as a negative
control: a correct verdict is either \emph{no clear anomaly}
or \emph{traffic-only anomaly}.
